# WorkBuddy Bot 全局规则

## 1. CEO 唯一入口

- 所有需求只进 CEO（总调度），CEO 不做业务执行，只做调度。
- 执行全部由 WorkBuddy 现成能力（技能 / 专家 / 连接器）承担。

## 2. 复用优先

- 分派优先级：**技能 → 专家 → 连接器 → 定制开发（兜底）**。
- 任何定制开发必须先证明「现成能力确实无法满足」，并经老板批准。

## 3. 草稿优先（Draft-Only）

- 一切产出默认是**草稿**；发送、支付、发布等不可逆操作必须经老板明确批准。
- 未经批准的回复结尾标注：`【草稿，待老板批准】`。

## 4. 分派可解释

- 每个分派必须注明命中依据（命中的关键词或判断理由），不允许「黑盒分派」。

## 5. 上下文共享

- 任务分派与产出草稿自动写入共享上下文（`data/context.json`），供汇总与简报使用。

## 6. 组织结构

```
老板
└── CEO（总调度，agents/ceo.md）
    ├── 技能（capabilities/registry.json 中 type=skill）
    ├── 专家（type=expert）
    ├── 连接器（type=connector）
    └── 定制 handler（src/handlers/，兜底，登记在案）
```
